## 1. 故障处理原则

故障处理目标是先恢复服务，再定位根因，最后完成复盘。处理人员应记录发生时间、影响范围、request_id、错误现象、已执行操作和恢复结果。

禁止在未确认影响的情况下直接删除数据卷、清空缓存或重建数据库。涉及数据安全事件时，同时遵循 E007 的报告要求。

## 2. 分级建议

| 级别 | 影响示例 | 响应原则 |
|---|---|---|
| P1 | 核心服务整体不可用或疑似数据泄露 | 立即通知负责人，优先止损 |
| P2 | 主要功能大范围不可用 | 尽快恢复并持续更新状态 |
| P3 | 部分请求失败，有可行绕行方案 | 排查并安排修复 |
| P4 | 低影响问题或一般咨询 | 纳入常规处理 |

此分级仅为模拟项目约定，不是现实组织的服务等级承诺。

## 3. API 请求超时

**现象**：客户端请求 FastAPI 接口超时，或模型生成接口长时间无响应。

排查步骤：

1. 使用 request_id 查询应用日志。
2. 判断耗时发生在 API 处理、数据库查询、向量检索还是模型供应商调用。
3. 检查外部 HTTP 客户端是否配置连接超时和读取超时。
4. 检查并发量、限流和连接池等待。
5. 对可重试的瞬时错误采用有上限的指数退避，并加入随机抖动。
6. 对非幂等操作，重试前确认是否会重复创建资源。

不得无限重试。超时阈值应按具体依赖和用户体验目标配置，而不是所有接口共用一个极大值。

## 4. 数据库连接失败

**现象**：日志出现连接拒绝、认证失败或连接池耗尽。

| 日志现象 | 可能原因 | 处理方式 |
|---|---|---|
| Connection refused | 数据库未启动或地址错误 | 检查容器状态和主机名 |
| password authentication failed | 凭据不匹配 | 检查 Secret / 环境变量，不在日志打印密码 |
| too many connections | 连接泄漏或连接池过大 | 检查连接释放和连接池配置 |
| timeout expired | 网络拥塞或数据库负载高 | 检查网络、慢查询和资源指标 |

Docker Compose 网络内应使用服务名 `postgres`，不能把容器内的 `localhost` 当作另一个容器。

## 5. Qdrant 检索异常

**现象**：检索返回空结果、请求失败或向量维度错误。

排查步骤：

1. 确认 Qdrant 容器运行正常。
2. 检查 Collection 是否存在。
3. 检查查询向量维度是否与 Collection 配置一致。
4. 检查文档是否成功写入，Point 数量是否符合预期。
5. 检查 metadata filter 是否过严。
6. 检查 document_id、tenant_id 等过滤字段是否写入正确。

如果更换了 Embedding 模型，应确认旧索引是否需要重新生成，不能假设不同模型的向量可以直接比较。

## 6. 模型 API 调用失败

**现象**：模型 API 返回认证错误、限流、服务不可用或响应格式异常。

- 401：检查 API Key 是否存在、是否有效，以及 Base URL 是否正确。
- 403：检查账号权限、模型权限或服务端策略。
- 429：降低请求速率，遵守服务端重试提示。
- 5xx：判断是否为服务端暂时故障，采用有限次数重试。
- 超时：分别设置连接超时和读取超时，并记录耗时。
- 返回内容为空：检查流式响应消费逻辑、finish reason 和异常分支。

密钥处理遵循 E007；模型调用参数和流式处理遵循 E008。

## 7. Docker 容器异常

执行：

```bash
docker compose ps
docker compose logs --tail=200 api
docker compose logs --tail=200 postgres
docker compose logs --tail=200 qdrant
```

若容器反复退出，应先查看日志和退出码，不要立即执行删除卷操作。部署与回滚流程参照 E004。

## 8. 事件记录模板

```markdown
# 事件记录：INC-DEMO-001

- 发生时间：<YYYY-MM-DD HH:MM timezone>
- 发现时间：<YYYY-MM-DD HH:MM timezone>
- 影响系统：<SERVICE>
- 影响范围：<SCOPE>
- 现象与错误码：<OBSERVATION>
- request_id：<REQUEST_ID>
- 临时缓解措施：<MITIGATION>
- 根因：<ROOT_CAUSE>
- 修复版本：<VERSION>
- 后续行动：<ACTION_ITEMS>
```

所有尖括号字段均需替换为实际记录。不得在事件记录中粘贴访问令牌、密码或完整个人敏感信息。

## 9. 复盘要求

复盘应关注系统性原因，而非简单归咎个人。至少记录时间线、影响、根因、检测为何未提前发现、恢复步骤和防止复发的行动项。
