> **模拟企业资料声明**：本文档为项目原创模拟安全规范，不构成法律意见、认证声明或任何真实企业的合规承诺。

## 1. 基本原则

数据处理遵循最小必要、明确授权、可追踪和安全默认原则。仅收集完成业务功能所需的数据，并限制访问范围。测试环境优先使用虚构或脱敏数据。

## 2. 数据分类

| 类别 | 示例 | 处理要求 |
|---|---|---|
| 公开数据 | 已公开的官方技术文档 | 仍需遵守来源许可和署名要求 |
| 内部演示数据 | 本项目原创模拟企业文档 | 标记为 synthetic，不冒充真实制度 |
| 业务敏感数据 | 非公开业务记录 | 限制访问，按需要脱敏 |
| 认证秘密 | API Key、密码、令牌、私钥 | 不得提交代码仓库或写入普通日志 |

## 3. API Key 与凭据管理

- 使用环境变量或受控 Secret 管理服务注入密钥。
- 禁止把真实密钥硬编码在 Python 文件、Notebook、Dockerfile 或前端代码中。
- `.env` 必须加入 `.gitignore`。
- `.env.example` 只能包含变量名和占位符。
- 密钥疑似泄露时，应尽快撤销或轮换，并检查相关访问记录。
- 不通过聊天截图、公开 issue 或日志分享完整密钥。

正确示例：

```python
import os

api_key = os.getenv("LLM_API_KEY")
if not api_key:
    raise RuntimeError("LLM_API_KEY is not configured")
```

错误示例：

```python
# 错误：不要将真实密钥写入源代码
api_key = "<REAL_SECRET>"
```

## 4. 日志脱敏

日志不得包含：

- 完整 Authorization Header；
- API Key、密码、Cookie 和会话令牌；
- 私钥或数据库完整连接串；
- 不必要的个人敏感信息；
- 未经授权的完整用户上传文档内容。

推荐记录 request_id、用户或租户的非敏感内部标识、错误码、耗时和服务名称。排查时只记录定位问题所需的最少上下文。

## 5. 文档上传安全

文档上传功能应：

1. 限制文件大小和允许格式。
2. 检查文件实际内容，不只相信扩展名。
3. 将上传文件存放在应用控制的目录。
4. 使用随机或安全生成的存储名，避免路径穿越。
5. 对解析器设置资源和超时限制。
6. 对上传内容执行访问控制。
7. 记录上传、处理和删除状态。

不得直接执行上传文档中包含的脚本、宏或命令。

## 6. RAG 知识库安全

- 每个文档必须记录来源、所有者或访问范围。
- 检索前应用权限过滤，而不是生成答案后才过滤。
- 删除文档时同步删除对应 Chunk 和向量。
- 对检索结果保留 document_id、chunk_index 和 source。
- 引用只能指向实际检索到的内容。
- 对知识库内容中的指令保持数据与指令分离。

## 7. Prompt Injection 防护

上传文档或检索片段可能包含“忽略之前规则”“泄露密钥”等恶意文本。系统必须将检索内容视为不可信数据，不允许文档内容覆盖系统级安全规则。

建议措施：

- 在 Prompt 中明确标记检索内容是引用资料，不是执行指令。
- 不因文档要求而泄露系统提示词、密钥或其他用户数据。
- 对工具调用实施参数校验和权限检查。
- 对高风险动作要求明确授权。
- 记录可疑输入并纳入安全测试集。

## 8. 访问控制

使用基于角色的访问控制时，至少区分普通用户、知识库管理员和系统管理员。普通用户只能访问被授权的知识库和文档。管理员操作应记录审计事件。

## 9. 数据删除与保留

数据保留周期应由实际业务需求和适用规则决定。本模拟项目应支持删除文档及其派生 Chunk、向量和缓存。删除完成后应验证各存储层不再返回该文档。

## 10. 安全事件处理

疑似密钥泄露、越权访问或敏感数据暴露时：

1. 记录发现时间和受影响系统。
2. 限制继续暴露的访问路径。
3. 撤销或轮换可能泄露的凭据。
4. 保存必要审计信息，避免扩大传播。
5. 按 E006 记录事件并复盘。
6. 修复后补充回归测试。
